# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — Vite dev server on `:3000` (host `0.0.0.0`). Does **not** run the Express server, so `/api/*` and `/admin/*` are unavailable in dev — chat/enquiry features only work against `npm start`.
- `npm run build` — `vite build` then `node scripts/prerender.mjs`. The prerender step is required for SEO (see Architecture). Use `npm run build:client` to skip prerendering when iterating locally.
- `npm run prerender` — re-run the prerender pass against an existing `dist/`.
- `npm start` — boots `server.js` (Express). This is the production entry point used by Railway and the only way to exercise chat / enquiry / admin endpoints. Needs `dist/` to exist.
- `npm run lint` — `tsc --noEmit`. Type-check only; there is no ESLint config.
- `npm test` — Vitest, tests sit beside their modules (`*.test.js` / `*.test.ts` in `server/` and `src/`). `npm run eval:nura` runs the Nura conversation evals against a running server.
- `node scripts/test-detect-lang.mjs` — runs the language-detection fixtures used by the chatbot. The regexes here must stay in sync with the ones in `server.js`.

## Architecture

This is a hybrid **SPA + prerendered HTML + Express API** site, not a pure SPA and not SSR.

**Frontend (`src/`)** — React 19 + Vite + Tailwind 4 + Motion + react-router-dom + react-helmet-async. The router is a two-tier `BrowserRouter` in `src/App.tsx`: a top-level `<Routes>` switches between (1) `/admin` → standalone `AdminPage`, (2) `/` → standalone `HeroLanding` (cinematic splash, no navbar/footer/chatbot), and (3) `*` → the normal site chrome (TopCtaBar + Navbar + Footer, or the investor footer on investor pages, + Chatbot) wrapping a nested `<Routes>` for `/home`, `/ecosystem`, `/products`, the investor pages (below), `/board-of-directors`, `/media-hub`, `/careers`. **The rich home content lives at `/home`, not `/`** — `/` is the cinematic landing splash; the Enter button navigates to `/home`. All internal "Home" links (navbar logo, breadcrumbs, "Back to Home" buttons) point at `/home`. Most page-level components live inline in `App.tsx` (~2100 lines); `Chatbot`, `AdminPage`, `HeroLanding`, `SEO`, the enquiry form and the investor pages are extracted to `src/components/`. When making page edits, expect to grep within `App.tsx` rather than hunting for separate files.

**Investor pages (`src/components/Investors/`)** — an as-is port of the separate Nuren investor site (Next.js + MongoDB, `c:\laragon\www\Nuren investor site`), in its NSX look (navy `#24315f` title bar, coral `#ee5174`, brown `#a86a4f`, Jost; Urbanist on the prospectus). Styles live in `investors.css`, scoped under `.ir-root`, not Tailwind. Routes: `/investors/company`, `/investors/corporate-governance` (+ `/:slug` for each of the 13 governance PDFs, listed in `src/data/investors/governanceDocs.js`), `/investors/announcements` (+ `/:slug`), `/investors/reports` (+ `/:slug`), `/investors/prospectus` (+ `/preview`, a Google Drive embed; not in the nav, as on the source), and `/pdf-viewer?src=`. The `/:slug` pages show one document in a toolbar-less iframe viewer, as the live investor site does; the viewer only embeds the investor S3 bucket's PDFs and `/api/files/<uuid>` (see `pdfSrc.ts`). The navbar has the source's Investors submenu; its parent link goes to Corporate Governance. Copy is verbatim from the source, typos included ("Little Colins Street", "COMMITTE CHARTERS"); page titles follow the live nurengroup.com. **Documents are not in this repo:** like the investor site, every PDF lives in its S3 bucket `nurengroup.com` (ap-southeast-1) at `announcement/pdf/<slug>.pdf`, `finance-report/pdf/<slug>.pdf` and `corporate-governance/pdf/<slug>.pdf`; slugs follow the source's rule (`slugify` in `validate.js`). Announcement and report tables start from the seed in `src/data/investors/*.seed.json` (imported from the live nurengroup.com API, so prerendered HTML has every row) and then load the live list from `/api/getAnnouncements` / `/api/getFinancialReport`. Release dates are timezone-less wall-clock strings, formatted field by field in `format.ts`, never through `Date`. Old URLs (`/investors`, `/investors/governance-documents[/:id]`, the source's `/investors/company-information` etc.) 301 via `server/investors/redirects.js`, which the router also uses client-side. **Footer:** `/investors/*`, `/pdf-viewer` and `/careers` render `InvestorFooter` (the live nurengroup.com footer: 38 Quicklinks pills, menu, copyright, social icons, phone) instead of the site `Footer`; `SiteFooter` in `App.tsx` picks it via `usesInvestorSiteFooter`. Its links are in `src/data/investors/footerLinks.ts`. Labels, order and outbound URLs come from the live site. Its internal pages map to this site's: `/mediahub` → `/media-hub`, `/brands/our-brands` → `/products`, both 301ed by `redirects.js`. Enquiry and Contact Us open the Contact Us window, and a direct `/enquiry` visit opens it over `/home`.

**Careers (`src/components/Careers/`)**: `/careers` is the investor site's careers page ported as-is, like the investor pages. It has the banner, team photo, photo strip and open positions. Styles are in `careers.css`, scoped under `.cr-root`, with values from the source SCSS, and the images are in `public/careers/`. Positions come from `src/data/careers/job-positions.seed.json` (imported from live's `/api/getJobPosition`), then `/api/getJobPosition` (open positions only). The admin's **Careers** tab (`JobPositionsPanel`) adds, edits, opens/closes and deletes them, and they're stored in `job-positions.json` in `INVESTOR_DATA_DIR` (`server/careers/`). Descriptions are HTML from the tab's small rich-text box (`RichTextEditor`), rendered with `dangerouslySetInnerHTML`. The server sanitises them on every save (`server/careers/sanitize.js`, `sanitize-html`, server-only; keep it out of browser imports), and `seed.test.ts` checks the seed is already sanitised. APPLY links to `/enquiry?job=<position>` as on live and opens the Contact Us window as the `career` enquiry type ("Job application"), with the message `<position> Application` and the attachment labelled as a resume. So job applications go to the same inbox and Leads store as other enquiries.

**Hero landing (`src/components/Hero/HeroLanding.tsx`)** — fullscreen cinematic splash at `/`. Looping muted background video (`public/hero/hero_section_video.mp4`, path set by `HERO_VIDEO_SRC` at the top of the file) with two-layer rendering: a blurred `object-cover` ambient backdrop `<video>` plus an `object-contain` foreground `<video>` so the full frame is always visible regardless of viewport aspect ratio. Keep the video H.264 MP4 (plays on every iOS/Android browser) and small — it's committed to git. `muted` is also set as an HTML attribute in an effect because React only sets it as a property, and the prerendered HTML would otherwise ship an unmuted (autoplay-blocked) video. `prefers-reduced-motion` holds the first frame; if autoplay is refused (iOS Low Power Mode) playback retries on first tap. The page sets its head tags through the shared `SEO` component (canonical `/home`) and `bg-black!` on `<body>` via Helmet so iOS landscape safe areas aren't white. The old `slide-XX.jpeg` files are still in `public/hero/` but unused. Type sizes use `clamp(min, vh-ideal, max)` so the layout adapts across laptop, monitor, phone, and fold cover screens without crashing the title into the Enter button on short viewports.

**Build pipeline** — `vite.config.ts` configures path alias `@/*` → repo root and **manual chunk splitting** for `react`/`react-router`, `motion`, `react-helmet-async`, `lucide-react`. Don't collapse those chunks back into the main bundle: a deploy that only changes `App.tsx` would otherwise invalidate ~140KB of vendor cache (the comment in `vite.config.ts:14-19` explains why).

**Prerender step (`scripts/prerender.mjs`)** — after `vite build`, Puppeteer walks each route in `ROUTES` and writes `dist/<route>/index.html` files containing the fully-rendered DOM (with Helmet meta and JSON-LD already painted). Express serves these via `express.static` so Googlebot, ClaudeBot, GPTBot, etc. get real content instead of an empty `<div id="root">`. **When adding a new route in `App.tsx`, also add it to `ROUTES` in `scripts/prerender.mjs` and to `public/sitemap.xml`** — otherwise it won't be indexed. The landing `/` and rich home `/home` are both prerendered separately; the landing's `<link rel="canonical">` points at `/home` so the splash doesn't dilute SEO. Routes with open-ended params (e.g. `/pdf-viewer?src=`) stay client-rendered and rely on the SPA fallback in `server.js`; the governance document pages have a fixed slug list, so `ROUTES` prerenders them from `governanceDocs.js`. The prerender runs on a static server, so `/api/*` doesn't exist there: pages that fetch data must render something useful without it (the investor tables use their bundled seed). **Head tags:** React 19 (which react-helmet-async v3 renders through) adds `<title>`/`<meta>`/`<link>` to the head instead of replacing them, so `main.tsx` calls `removeStaticHeadTags()` (in `SEO.tsx`) before rendering. It strips index.html's site-wide set, or a prerendered page's own set, so each page ends up with one title, description, canonical and set of share tags. A new page-level head tag that `SEO` renders must also go in that function's selector list.

**Backend (`server.js`)** — single-file Express app. Responsibilities:

- `POST /api/chat` — calls Anthropic (`claude-haiku-4-5-20251001`) with the `NUREN_KNOWLEDGE` system prompt baked into `server.js:17-239`. The full Nura sales playbook (positioning, ecosystem, audience stats, services, sales flow, objection handling, push-to-form triggers, guardrails, 2026 media kit facts) lives in this string — **edit it directly to update the chatbot's behaviour, not from the admin UI** (the admin UI shows it read-only). The frontend uses Gemini-style `role: 'user' | 'model'` history; `toAnthropicMessages` maps `model` → `assistant` at the boundary.
- **Language override** (`server.js:436-522`) — Haiku 4.5 has a stubborn English default for marketing-context replies, so we don't trust the model to follow the in-prompt LANGUAGE rule. `detectReplyLanguage` runs hard regex heuristics (`HAN_RE` for Han characters → Mandarin; `BM_MARKERS` word list → Bahasa Malaysia) over the current message and last 3 user turns, then `languageDirective` appends a CRITICAL OVERRIDE block to the system prompt. The detected language is exposed via the `X-Nura-Lang` response header for debugging. If you change the BM marker list, update `scripts/test-detect-lang.mjs` to match.
- `POST /api/enquiry` — the one lead-capture endpoint, used by both the **Contact Us window** (`src/components/Enquiry/ContactModal.tsx`, opened from the navbar / "Get a Proposal" buttons) and the **chat's "Talk to our team" form**. Both render the shared `EnquiryForm`, laid out like motherhood.com.my/contact-us: enquiry type, name, email, mobile, brand, message, plus (for campaign types) target audience, campaign period, budget range, and an optional **brief attachment**. Field rules live in `server/leads/enquiry.js` and are imported by the browser too, so client and server can't drift; the server re-validates everything. The brief arrives as base64 in the JSON body (4 MB cap, extension allow-list plus magic-byte check, in `server/leads/attachment.js`); this route alone has a 6 MB body limit (everything else stays 64 KB) and is rate-limited per IP (5/hr) *before* the body is parsed. Each lead is emailed via Resend (to `ENQUIRY_RECIPIENT`, plus `ENQUIRY_CC` if set, brief attached) and saved by `server/leads/store.js`. Includes a `website` honeypot and CR/LF stripping on single-line fields (header injection).
- **Lead storage** — leads are appended to `leads.jsonl` and briefs saved as files under `LEADS_DIR` (default `./data`, git-ignored). Railway's disk is wiped on deploy, so **mount a Railway volume and set `LEADS_DIR` to it** to keep them; the admin Leads tab warns when that isn't set. The email is the primary record; the store is the searchable copy. Unlike the old design (hashed email only), the store holds full contact details (the sales team asked for a dashboard), so it sits behind admin auth and is a PDPA data store.
- `POST /api/chat/brief` — fills the enquiry form from the chat (type, brand, audience, period, budget, and name/email/phone if the visitor typed them). Names, brand, email and phone are kept only if they appear word for word in the visitor's own messages (`parseBrief` checks), so the model can't invent contact details.
- `/admin/*` — Basic Auth (against `SUPERADMIN_PASSWORD`) with timing-safe compare, 5-failure / 15-minute IP lockout, and a generic "Admin access unavailable" 503 when the password env var is unset (deliberately doesn't name the env var to avoid giving an attacker the exact key to look for).
- **Investor records (`server/investors/`)** — the admin's Announcements and Finance Reports tabs (ported from the investor site's admin: search, add, edit, hide/show, delete, optional PDF/DOC/DOCX upload). `store.js` keeps each collection as a JSON file under `INVESTOR_DATA_DIR` (default `./data/investors`), seeded from `src/data/investors/*.seed.json` on first boot, with atomic writes; like leads, **point it at the Railway volume** (`/data/investors`) or admin edits vanish on deploy. New records get a slug from their headline/title (unique, kept on later edits). **Uploads go to the investor S3 bucket** (`s3.js`, signed with `aws4fetch`) once `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` are set: named `<folder>/pdf/<slug of the title>.pdf`, never overwriting (S3 `If-None-Match: *`, then `-2`, `-3`…), and checked to be publicly readable. Without the keys, uploads stay on the volume and are served at `/api/files/:id`. `routes.js` serves the public lists with the source's response shape (`{ data: { data, totalDocs }, success }`), uploads, and the admin API (`/admin/api/announcements`, `/admin/api/financial-reports`, `/admin/api/files`); every admin change also refuses cross-site requests (`Sec-Fetch-Site` / `Origin`), and uploads check the password before reading the 25 MB body. `validate.js` holds the field rules and is imported by the admin form too; record links may only be S3/https URLs or server uploads. The source's admin used a forgeable `nurengroup_admin=true` cookie; here it's the normal admin login.
- **Rate limiting** uses `lru-cache` with TTL — there is no Redis, so limits are per-process and reset on restart. Three independent buckets: chat (20/min), enquiry (5/hr), admin (60/min, enough for editing announcements; logins are still capped by the lockout). The visitor's IP comes from `server/client-ip.js`, which reads Railway's `X-Real-IP` (falling back to the socket address locally); Express `trust proxy` is off. Don't key on `X-Forwarded-For`: on Railway its last entry is a changing Railway address (so a hop count puts unrelated visitors in one bucket), and its first entry is only honest because Railway rewrites it. If a proxy such as Cloudflare is put in front, `X-Real-IP` becomes that proxy's address and needs revisiting. The admin Overview shows "Your IP, as rate limits see it" to confirm limits key on the visitor, not a Railway address. Admin passwords are compared with `server/secure-compare.js` (SHA-256 + `crypto.timingSafeEqual`, no length leak); `/admin/api/*` responses are `Cache-Control: no-store`.
- **Security headers** via Helmet with a hand-tuned CSP that allows YouTube/Instagram iframes (and Google Drive, for the prospectus preview, and `s3.ap-southeast-1.amazonaws.com`, for the investor PDFs); `connectSrc` is `'self'` only because the chat call is server-side, never browser → Anthropic. `referrerPolicy` is `strict-origin-when-cross-origin` (not Helmet's `no-referrer` default) because YouTube embeds need a Referer to validate origin. The CSP sets `frame-ancestors 'none'` site-wide, which would blank a server-hosted PDF inside the viewer's iframe, so `/api/files/:id` PDFs override it with `frame-ancestors 'self'` (S3 sends no such header).
- **Static serving** sets `Cache-Control: max-age=0, must-revalidate` on `.html` (so deploys propagate immediately) and `max-age=31536000, immutable` on hashed `assets/*.{js,css,woff2}`. The path-normalisation regex is built to work on Windows (`\\` → `/`). The SPA fallback adds `X-Robots-Tag: noindex, nofollow` for `/admin` and `/api` paths.

**Deployment** — `railway.json` defines the Railway build (`npm install && npm run build`) and start (`node server.js`) with `/healthz` as the healthcheck. `nixpacks.toml` adds `unzip` to the build image: Puppeteer 25+ needs it to unpack the Chrome that prerendering uses, and without it the download fails silently in `npm ci` and the build stops at prerender with "Could not find Chrome". **Ignore the Netlify instructions in README.md** — those are stale; production runs on Railway via the Express server. Required env vars: `ANTHROPIC_API_KEY`, `RESEND_API_KEY`, `SUPERADMIN_PASSWORD`. Optional: `LEADS_DIR` (volume path for the lead store), `INVESTOR_DATA_DIR` (volume path for investor records), `AWS_ACCESS_KEY_ID` + `AWS_SECRET_ACCESS_KEY` (+ optional `S3_BUCKET`, `AWS_REGION`; admin uploads to the investor S3 bucket), `ENQUIRY_CC` (comma-separated extra recipients, e.g. the sales team), `ENQUIRY_FROM_EMAIL` (must be from a Resend-verified domain — fallback uses Resend's sandbox sender which only delivers to the Resend account owner), `ENQUIRY_RECIPIENT`, `PORT`, `DISABLE_HMR`.

**TypeScript config** — `noEmit: true`, `allowImportingTsExtensions: true`, `allowJs`, `resolveJsonModule`, `jsx: react-jsx`. `tsconfig.json` is the only config; there's no `tsconfig.node.json` for the scripts (they're `.mjs`). There is no `@types/react`, so the editor shows JSX "implicitly any" errors that `npm run lint` doesn't; one real consequence is that `key` on your own components fails `tsc`, so map to keyed intrinsic elements (or render functions) instead.

**Styling tokens (`src/index.css`)** — Tailwind 4 `@theme` block defines `--color-nuren-pink` (`#FF6B9E`), `--color-nuren-purple` (`#7E57C2`), and three font tokens: `--font-sans` (Inter, body default), `--font-display` (Outfit, headings), and `--font-montserrat` (used on the hero landing). Fonts are self-hosted via `@fontsource-variable/*` packages imported in `main.tsx` (the investor pages import Jost and Urbanist themselves). To change a brand color globally, edit the token here — only override with `text-[#hex]` arbitrary values when you specifically want a one-off (the hero title is an intentional one-off at `#ee5174`).
